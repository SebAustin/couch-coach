# Deploying the TV app (sideload to Fire TV)

There is no store or cloud step for the TV app: it is one APK installed over adb. Nothing here spends money or
touches AWS. The cloud side (API, AppSync, CloudFront) is deployed by `infra/` and only *read* by this app via
`infra/client-config.json`.

## Environment config

| What | Where | Notes |
|---|---|---|
| API base URL, AppSync hosts, public API key, phone URL | `packages/shared-ui/src/config.generated.ts`, generated from `infra/client-config.json` by `yarn sync` | The key is a public client key scoped to `/cc/*`, expires 2026-12-15. Re-run `yarn sync` and rebuild after any `cdk deploy` that changes outputs. |
| Package id, version, permissions, cleartext policy | `apps/expo-multi-tv/app.json` | `versionCode` must increase for upgrade installs. |
| Signing | Expo debug keystore, generated by prebuild | Sideload only. A store submission would need a real keystore (not needed for the hackathon). |
| Dev/stage/prod split | none | One stack, one config. To point a build at another stack: `yarn sync -- --config path/to/other-client-config.json` (or `node scripts/sync-shared.mjs --config ...`). No secrets are committed or read from env. |

## Build (local, reproducible)

```bash
cd apps/tv && source scripts/android-env.sh
yarn install && yarn test && yarn typecheck && yarn sync:check
yarn build:apk                       # -> dist/couch-coach.apk
```

Verified signature and manifest: `apksigner verify --print-certs dist/couch-coach.apk`;
`aapt2 dump badging dist/couch-coach.apk` shows `dev.sebaustin.couchcoach`, `LEANBACK_LAUNCHER`, banner, INTERNET.

## Rollout (gated: needs the physical Fire TV, so the owner runs it)

1. Fire TV: Settings > My Fire TV > Developer Options > ADB debugging ON; note the IP (About > Network).
2. `adb connect <ip>:5555` and accept the prompt on the TV.
3. `yarn install:apk <ip>` (`adb install -r dist/couch-coach.apk`; launches the app).

## Smoke test (2 minutes, on the TV)

1. App opens on "Who's working out?" with the Members from the API (Health: if you see "Can't reach Couch Coach",
   the TV has no internet or the API is down; it retries every 10 s).
2. Select a Member: QR appears, "Code expires in ..." counts down.
3. Phone scans, joins: "Phone connected" for 0.8 s, then Live with the skeleton moving.
4. Stand and squat: rep counter increments, Form Score colours, a Fault shows a red limb and a chip.
5. End the Set on the phone: "Coach is thinking", then the Cue card and spoken audio ("Playing").
6. Press **Menu** on Live: debug overlay (draw fps near 30, latency, socket "connected").
7. Back (twice) > "End this Session?" > End session > Recap > Done > Members. Back on Members exits the app.

No phone? `node scripts/publish-synthetic.mjs` + the printed `adb ... couchcoach://attach?...` command exercises
steps 3-7 with synthetic data (see README).

## Observability

- Logs: `adb logcat -s ReactNativeJS:V AndroidRuntime:E` (the app logs nothing in release except fatal errors).
- Health signals visible on screen: the connection pill (Phone connected / Reconnecting... / Phone lost), the
  "Lost connection to Couch Coach." card, and the debug overlay (Menu key).
- Crash triage: `adb logcat -d | grep -A20 "FATAL EXCEPTION"`.

## Rollback

`adb uninstall dev.sebaustin.couchcoach` (loses nothing: Members and history live in the cloud), or reinstall the
previous APK with `adb install -r` (same signing key, `versionCode` not lower). Keep the last known-good APK
outside `dist/` (it is gitignored).

## Feature flags

None. The only runtime switches are the debug overlay (Menu key) and the `attach` deep link (demo/debug; carries no
secret). To disable the deep link, remove `useAttachLink` from `navigation/CouchCoachApp.tsx`.

## Known gaps

- Not run on a physical Fire TV yet (emulator: Android TV 14, 1080p, arm64).
- APK still bundles x86/x86_64 native libs from prebuilt dependencies (about 15 MB of dead weight).
- Cue audio verified on the emulator with a public MP3; Polly presigned URLs (15 min) are untested on-device.
